## P0 — Критические

### BACKLOG-001: Web UI для настройки параметров ретуши

**Статус**: ✅ Done — Фаза 3 завершена (FastAPI backend + React frontend + пресеты + Makefile)
**Создано**: 2026-05-04

**Проблема**:
Настройка параметров обработки (яркость, glow, face_brightness_target и т.д.) сейчас делается через ручное редактирование `config.yaml`. Это крайне неэффективно: нужно менять значение → запускать CLI → открыть результат → оценить → повторить. Параметры связаны нелинейно (brightness + face_brightness_target + glow_size), и подобрать их комбинацию вслепую невозможно.

**Что нужно**:
Web-интерфейс для настройки параметров ретуши с **живым предпросмотром** результата. Пользователь двигает слайдер → видит обновлённый результат на лету (или после нажатия «Применить»).

**Функциональные требования**:

1. **Панель параметров** (слайдеры + числовые поля):
   - По группе `processing.laser` и `processing.impact`:
     - `brightness` (0.5–1.5, шаг 0.01)
     - `face_brightness_target` (min/max, 50–255)
     - `glow_size_min` / `glow_size_max` (5–100 px)
     - `glow_opacity_min` / `glow_opacity_max` (10–100%)
   - По группе `processing` (общие):
     - `blue_threshold` (10–80)
     - `fringe_radius` (0–10)
   - По группе `vignette`:
     - `vertical_offset` (0.0–0.3)
     - `vertical_diameter` (0.2–0.8)
     - `blur_radius` (10–120)
     - `headroom` (0.2–1.0)
     - `horizontal_oversize` (0.0–0.5)
   - Переключатель станка: laser / impact

2. **Предпросмотр результата**:
   - Загрузка исходного PNG (drag & drop или выбор файла)
   - Отображение «до / после» (side-by-side или слайдер-компаратор)
   - Отображение промежуточных этапов: после хромакея, после glow, после brightness, после vignette
   - Гистограмма яркости (общая + по маске лица)

3. **Панель диагностики**:
   - Средняя яркость по маске лица (с/без glow-исключения)
   - Процент пересвеченных пикселей (> 250)
   - Процент чёрного фона в результате
   - Размер glow и opacity, применённые к текущему изображению

4. **Сохранение конфигурации**:
   - Кнопка «Сохранить config.yaml»
   - Кнопка «Экспорт TIFF/PNG» с текущими параметрами
   - Пресеты: сохранить/загрузить набор параметров

5. **Техническая реализация**:
   - Next.js 16 + React (shadcn/ui компоненты)
   - Backend API: `POST /api/process` — принимает параметры + изображение, возвращает результат
   - Backend вызывает `retouch.processing.pipeline.process()` напрямую (не через CLI)
   - Предпросмотр на уменьшенной копии (max 1024px по длинной стороне) для скорости
   - Финальный экспорт — в полном разрешении

**Критерии приёмки**:
- [x] Web UI запускается через `npm run dev` или `make ui`
- [x] Можно загрузить PNG и увидеть результат обработки
- [x] Изменение любого слайдера обновляет предпросмотр за < 3 сек
- [x] Можно сохранить config.yaml из UI
- [x] Можно экспортировать TIFF/PNG в полном разрешении
- [ ] Гистограмма и диагностика отображаются корректно (гистограмма не входила в план v3.4, будущая задача)

### BACKLOG-002: Пересвет воротника — коррекция применяется глобально

**Статус**: ✅ Done — face_region_top добавлен (Pre-0), замер яркости по верхней части маски (Фаза 0)
**Создано**: 2026-05-04
**Зависит от**: BACKLOG-001 (Web UI ускорит отладку)

**Проблема**:
`check_face_brightness()` измеряет среднюю яркость по всей маске субъекта (включая воротник, одежду) и применяет коррекцию ко всему изображению. Воротник уже светлый (160-200), и даже curves-коррекция (которая меньше трогает света) добавляет ему 10-20 единиц, доводя до пересвета (> 250).

**Что нужно**:
1. Использовать **отдельную маску лица** (верхняя 40-50% маски субъекта) для замера яркости, а не всю маску целиком. Лицо всегда в верхней части портрета.
2. Коррекцию яркости применять **только к области лица**, а не ко всему изображению.
3. Или: добавить параметр `face_region_ratio` (доля высоты маски сверху, которая считается «лицом»).

**Варианты реализации**:
- A) Простая эвристика: верхние N% маски = лицо (параметр `face_region_top: 0.45`)
- B) Детекция лица через `opencv-python` (haarcascade) — точнее, но новая зависимость
- C) Сегментация лица через простую эвристику по яркости (лицо обычно темнее одежды)

**Критерии приёмки**:
- [x] Замер яркости делается только по области лица (не воротник)
- [x] Коррекция яркости не пересвечивает воротник
- [x] Результат визуально приемлем для портретов разного типа (поп, военный, гражданский)

### BACKLOG-005: GIMP-пайплайн — исправить или удалить

**Статус**: ✅ Done — пометка experimental (Pre-0, задача 5). GIMP сохранён.
**Создано**: 2026-05-04

**Проблема**:
GIMP-пайплайн (`retouch gimp`) технически работает (запускает GIMP, выполняет Script-Fu), но даёт неприемлемые результаты: пересвет, белый фон, неправильные параметры для impact. Все усилия по отладке шли через Pillow-пайплайн (`retouch process`), и GIMP-маршрут остаётся сломанным.

**Варианты**:
- A) Удалить GIMP-пайплайн полностью (рекомендуется — Pillow справляется)
- B) Переделать GIMP Script-Fu чтобы использовать те же параметры, что и Pillow
- C) Оставить как есть с пометкой «experimental / not recommended»

**Решение**: Вариант C — оставить как есть с пометкой «experimental / not recommended».
GIMP-пайплайн не удаляется, но помечен как экспериментальный. Основной путь — Pillow (`retouch process`).

**Что нужно**:
1. Добавить предупреждение при запуске `retouch gimp`: «Experimental: results may be incorrect. Use `retouch process` for production.»
2. Пометить в документации и CLI help: experimental / not recommended
3. Не тратить время на исправление GIMP-результатов — Pillow справляется

**Критерии приёмки**:
- [x] CLI команда `retouch gimp` показывает предупреждение «experimental / not recommended»
- [x] CLI help помечает команду как experimental
- [x] AGENTS.md / README обновлены

### BACKLOG-006: Shadow noise для impact — реализация в Pillow

**Статус**: Partial — shadow_noise убран из конфига (Pre-0, задача 4), реализация — будущая задача (см. комментарий в docs/reference/config.md)
**Создано**: 2026-05-04

**Проблема**:
В config.yaml есть `impact.shadow_noise: true`, но в Pillow-пайплайне этот параметр **не используется**. Шум в глубоких тенях нужен, чтобы игла impact-станка не «застревала» в полностью чёрных областях (нет точек для удара).

**Что нужно**:
1. Добавить в `levels.py` функцию `add_shadow_noise(img_gray, threshold=30, amount=5)`
2. Для пикселей с яркостью < threshold: добавить случайный шум ±amount
3. Вызывать в pipeline.py при `machine_type == "impact"` и `shadow_noise == True`

**Критерии приёмки**:
- [ ] Параметр `shadow_noise` обрабатывается в Pillow-пайплайне
- [ ] Глубокие тени (< 30) получают шум ±5 единиц
- [ ] Результат визуально не отличается от оригинала (шум незаметен)
