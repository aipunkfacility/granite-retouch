# Новые фичи для пайплайна granite-retouch

> Источник: анализ транскриптов YouTube-роликов.
> Критерий: только то, что реально автоматизируемо в Python-пайплайне (Pillow/NumPy/SciPy)
> и улучшит выходное изображение для станков.

---

## 1. Декоративный фон «лучи» (Motion Blur) — 🆕 новая фича

Единственная **принципиально новая фича**, которой в проекте нет вообще. Клиенты просят — значит нужна. Алгоритм полностью автоматизируем:

```python
# Алгоритм
1. Генерация случайных тонких линий (жёсткая кисть на чёрном фоне)
2. scipy.ndimage.gaussian_filter1d с направлением → аналог Motion Blur
3. Дубликат → поворот на 180° → объединить
4. Ещё раз blur с бóльшим радиусом
5. Blend mode Screen: (a + b) - (a * b / 255)
6. Levels (подтянуть чёрный/белый)
7. Обрезать по маске виньетки
```

**Реализация:**

- Новый модуль: `retouch/processing/rays.py`
- Опция в конфиге: `background_style: rays | solid_black`
- Параметры: `rays_angle` (угол, по умолчанию 30°), `rays_count` (количество линий), `rays_blur` (смещение blur)

**Эталонный воркфлоу (из видео):**

1. Новый слой на чёрном фоне
2. Жёсткая белая круглая кисть → тонкие хаотичные линии за портретом
3. Фильтр «Размытие в движении»: угол 30°, смещение 100 px
4. Дубликат слоя → повернуть на 180°
5. Объединить оба слоя
6. Дубликат → снова Motion Blur с бóльшим смещением
7. Режим наложения «Экран» (Screen) → лучи поярче
8. Объединить с чёрным фоном → Levels (подтянуть чёрные и белые пиксели)
9. Опционально: обрезать по овальной области

**Статус:** ❌ Не реализовано

## 2. Unsharp Mask раздельно для одежды и лица — 📈 улучшение качества

Сейчас в пайплайне Unsharp Mask применяется ко **всей маске субъекта** целиком. А из видео: одежде нужна резкость, лицу — нет (или гораздо мягче). Это **ухудшает качество** — лицо пересушивается.

**Реализация:**

В `levels.py → apply_unsharp_mask()` разделить маску субъекта на две зоны:

- **Нижняя часть** (ниже центра лица → одежда): текущий/повышенный процент unsharp
- **Верхняя часть** (лицо + волосы): сниженный процент или вообще без unsharp

Определить границу можно через пропорции маски (верхние ~60% = лицо/голова, нижние ~40% = одежда) — грубо, но для станка достаточно. Никакого face detection не нужно.

**Параметры конфига:**

- `unsharp_face_percent` — процент для верхней зоны (лицо), по умолчанию ниже текущего или 0
- `unsharp_clothing_percent` — процент для нижней зоны (одежда), текущее значение

**Эталонный воркфлоу (из видео):**

1. Создать копию слоя
2. Применить фильтр «Контурная резкость» (Unsharp Mask)
3. Создать слой-маску, инвертировать в чёрный
4. Белой кистью раскрыть **только район одежды**
5. Лицо и волосы остаются без резкости

**Статус:** ❌ Не реализовано

## 3. Camera Raw Clarity для волос — 📈 улучшение качества

Видео применяет «чёткость/ДНК» (Clarity = локальный контраст) **только для волос**, отдельным проходом. В Python это **CLAHE** или **Unsharp Mask с большим радиусом и малым amount** — и это уже частично есть, но применяется ко всему изображению.

**Реализация:**

Добавить отдельный шаг «hair clarity» после glow, **только для зоны волос**. Зона волос ≈ верхняя часть маски субъекта выше линии глаз.

**Параметр конфига:**

- `hair_clarity` — интенсивность локального контраста для волос (0 = выключено)

**Алгоритм (на выбор):**

1. **CLAHE** (OpenCV): `cv2.createCLAHE(clipLimit=hair_clarity).apply(hair_zone)` — локальная гистограммная эквализация
2. **Unsharp Mask с большим радиусом**: радиус ~20–30 px, amount ~0.3–0.5 — усиливает среднечастотный контраст, аналогично Clarity в Camera Raw
3. **Маска волос** = верхняя ~30% маски субъекта (выше бровей)

**Эталонный воркфлоу (из видео):**

1. После прорисовки волос и Oil Paint
2. Группа слоёв волос → перенести выше → уменьшить непрозрачность группы
3. Camera Raw: прибавить параметр «Чёткость» (Clarity)
4. Усилить «Резкость» (Sharpening) для детализации
5. Осветлить тени, убрать текстуру
6. History Brush — вернуть эффект только по волосам (можно зацепить брови и глаза)

**Статус:** ❌ Не реализовано

## 4. Овал + Прямоугольник для ореола — 🔧 лёгкое дополнение

Сейчас `vignette.py` делает арку (эллипс). Видео показывает комбо:

- Овал (Feather 30–35 px) для верхней части
- Прямоугольник (Feather 0) для нижней

Это **другая форма нижнего края** — не полуокружность, а прямая. Легко добавить как режим `vignette_bottom: arch | flat` с Feather 30–35 px на стыке.

**Реализация:**

В `vignette.py` добавить второй режим маски:

- `arch` (текущий): эллипс на всю высоту
- `flat`: эллипс для верхней части + прямоугольник для нижней, стык с Feather 30–35 px

**Параметры конфига:**

- `vignette_bottom: arch | flat` — форма нижнего края
- `vignette_flat_feather: 30` — растушёвка на стыке овала и прямоугольника (в пикселях)

**Эталонный воркфлоу (из видео):**

1. Инструмент «Овальная область» → Растушёвка 30–35 px
2. Создать овал на изображении → трансформировать выделение
3. Инструмент «Прямоугольная область» → Растушёвка 0 px
4. Активна кнопка «Добавить к выделенной области»
5. Добавить прямоугольное выделение снизу
6. Инвертировать → залить чёрным

## 5. Белая аура через Gaussian Blur — 🆕 новый метод ореола

Альтернативный способ создания ореола (glow) вокруг портрета. Вместо Inner Glow (текущий метод в `glow.py`) — **белый силуэт субъекта + Gaussian Blur на отдельном слое ниже изображения**. Результат — мягкое белое свечение по контуру портрета, похожее на Outer Glow.

Отличие от текущего inner glow: аура распространяется **наружу** от контура, а не внутрь. Это даёт более выраженный, заметный на камне ореол, который заказчики часто просят.

**Реализация:**

В `glow.py` добавить второй метод:

- `inner` (текущий): Inner Glow — свечение внутрь субъекта
- `aura` (новый): белый силуэт + Gaussian Blur — свечение наружу

```python
# Алгоритм
1. Маска субъекта → залить белым на новом слое
2. Gaussian Blur с радиусом glow_size (из конфига)
3. Наложить слой ауры ПОД изображение субъекта
4. Регулировать интенсивность через opacity слоя ауры
```

**Параметры конфига:**

- `glow_style: inner | aura` — метод ореола
- `glow_size` — радиус Gaussian Blur (переиспользуется из текущего конфига)
- `glow_opacity` — непрозрачность слоя ауры (переиспользуется)

**Эталонный воркфлоу (из видео):**

1. Выделить субъекта
2. Создать новый слой НИЖЕ изображения субъекта
3. Залить выделение белым цветом
4. Снять выделение
5. Применить фильтр Gaussian Blur (радиус подбирается визуально)
6. Ластиком уменьшить ауру в районе плеч (опционально)
7. Корректировать opacity для нужной интенсивности

**Статус:** ❌ Не реализовано

## 6. Inpainting пересветов на лице — 📈 улучшение качества

Пересветы (clipping) на лице — белые или почти белые пятна, которые на камне превращаются в неестественно яркие области. Ретушёры убирают их вручную через Patch Tool или Заплатку. В автоматическом пайплайне можно детектировать такие зоны и залить их из окружающих пикселей.

Типичные зоны пересвета: кончик носа, зубы, лоб, скулы. После коррекции эти области становятся мягче и естественнее, что критично для станка — пересвет = переработка иглой.

**Реализация:**

Добавить шаг после `apply_levels()` и до `correct_face_brightness()` в `levels.py`:

```python
# Алгоритм
1. В зоне маски лица найти пиксели >= white_ceiling (из конфига)
2. Создать маску пересветов (бинарная)
3. Расширить маску на 1–2 px (dilate) для захвата границ
4. Inpainting: cv2.inpaint() с флагом INPAINT_TELEA
   — или: заменить пиксели на медиану окружающих непересвеченных
5. Сгладить границы blur'ом для бесшовного перехода
```

**Параметры конфига:**

- `fix_highlights: true | false` — включить/выключить коррекцию пересветов
- `highlight_threshold` — порог детекции пересветов (по умолчанию = white_ceiling из конфига)

**Эталонный воркфлоу (из видео):**

1. Инструмент «Заплатка» (Patch Tool): выделить пересвеченный участок
2. Отвести выделение на соседнюю чистую область
3. Заплатка автоматически подгоняет текстуру и тон
4. Конкретные зоны: кончик носа, зубы, блики на коже
5. Альтернативно: Quick Mask → выделить пересвет → Levels для осветления/затемнения

**Статус:** ❌ Не реализовано

## 7. Параметр неоднородности камня → адаптивные параметры пайплайна — 🔧 ключевой параметр

Источник: официальное видео САУНО по оценке качества ретуши в Engrave 7.2+.

Неоднородность (пятнистость) гранита **съедает контраст** изображения при гравировке. На мониторе ретушь выглядит хорошо, а на камне получается плоской и нечёткой. Чем выше неоднородность камня, тем агрессивнее нужно усиливать контраст, резкость и объём на этапе ретуши.

Программа Engrave использует параметр «Неоднородность» (Ctrl+F11) для симуляции, но требует подключённый станок. Пайплайн может учесть этот параметр **автоматически** — адаптируя Levels, Unsharp и Glow под качество камня.

**Реализация:**

Добавить параметр `stone_heterogeneity` в `config.yaml`. Он влияет на несколько существующих параметров:

| Параметр пайплайна | heterogeneity = 0 (идеальный камень) | heterogeneity = 2 (типичный) | heterogeneity = 5 (плохой камень) |
|---|---|---|---|
| `levels_factor` | текущее значение | ×1.2 | ×1.5 |
| `unsharp_percent` | текущее значение | ×1.3 | ×1.6 |
| `glow_opacity` | текущее значение | ×1.1 | ×1.2 |
| `face_brightness_target` | текущее | –5 | –10 |

**Параметр конфига:**

- `stone_heterogeneity: 0–5` — неоднородность камня (0 = идеальный, 2 = типичный по умолчанию, 5 = очень плохой)

**Эталонный воркфлоу (из видео Engrave):**

1. Ретушь → перенести в Engrave → включить предпросмотр гравировки
2. Изображение становится менее контрастным, детали теряются
3. Настроить «Неоднородность» (Ctrl+F11): установить значение 2
4. Сравнить: предпросмотр вкл/выкл
5. Если плоско → вернуться в Photoshop → увеличить контраст:
   - Яркость/Контрастность: уменьшить яркость, увеличить контраст
   - Levels: уменьшить гамму
   - Smart Sharpen: усилить резкость
   - Dodge/Burn: выправить пересветы/провалы после контраста
6. Повторять цикл до приемлемого результата

**Статус:** ❌ Не реализовано

## 8. Модуль симуляции гравировки на камне — 🆕 новая фича

Программа Engrave показывает предпросмотр результата гравировки, но **требует подключённый станок**. Пайплайн может реализовать собственную симуляцию — без зависимости от железа.

Цель: показать ретушёру, **как портрет будет выглядеть на камне**, до отправки на станок. Это позволяет выявить «плоские» участки, потерю деталей и проблемы с контрастом заранее.

**Реализация:**

Новый модуль `retouch/processing/stone_preview.py`:

```python
# Алгоритм симуляции гравировки на камне
1. Взять результат пайплайна (Grayscale L)
2. Уменьшить контраст пропорционально stone_heterogeneity:
   result = (img - 128) * (1 - heterogeneity * 0.08) + 128
3. Добавить шум текстуры камня:
   noise = perlin_noise(shape, scale=stone_heterogeneity * 20)
   result = result + noise * (heterogeneity * 5)
4. Сгладить полутона (слабый Gaussian Blur, sigma = heterogeneity * 0.5):
   result = gaussian_filter(result, sigma=heterogeneity * 0.5)
5. Clip в [0, 255], вернуть как L-изображение
```

**Интеграция с Web UI:**

- Кнопка «Симуляция на камне» рядом с превью
- Показать рядом: результат пайплайна | симуляция на камне
- Слайдер `stone_heterogeneity` — обновление симуляции в реальном времени

**Параметры конфига:**

- `stone_heterogeneity` — переиспользуется из фичи #7

**Эталонный алгоритм (из Engrave):**

1. Предпросмотр уменьшает контраст изображения
2. Детали теряются (полутона сливаются)
3. Неоднородность камня добавляет «шум» к результату
4. Чем выше неоднородность — тем сильнее эффект

**Статус:** ❌ Не реализовано

## 10. Целевое разрешение BMP — зависит от шага станка и типа камня — 🔧 ключевой параметр экспорта

Источник: руководство по эксплуатации График-3К (Manual_122a.pdf, разделы 11.5, 15.18).

Сейчас `export.py` сохраняет BMP **без контроля разрешения** — пиксели изображения переносятся как есть, а станок интерпретирует 1 пиксель = 1 удар (1 точка). Если физический размер гравировки не совпадает с задуманным — портрет растягивается или сжимается. Правильный BMP **должен** иметь разрешение, соответствующее шагу станка: именно тогда пиксель-к-точке даёт корректный масштаб.

**Формула из мануала САУНО:**

```
Resolution [pixels/cm] = 10 / Step [mm]
Resolution [dpi]       = 25.4 / Step [mm]
```

**Таблица соответствия шаг → разрешение:**

| Шаг (Engrave), мм | Разрешение, px/cm | Разрешение, dpi |
|---|---|---|
| 0.10 | 100.00 | 254.0 |
| 0.15 | 66.67 | 169.3 |
| 0.20 | 50.00 | 127.0 |
| 0.25 | 40.00 | 101.6 |
| 0.30 | 33.33 | 84.7 |
| 0.35 | 28.57 | 72.6 |
| 0.40 | 25.00 | 63.5 |
| 0.45 | 22.22 | 56.4 |
| 0.50 | 20.00 | 50.8 |

**Реализация:**

В `config.yaml` добавить параметры станка:

```yaml
machine:
  step_mm: 0.300        # шаг гравировки в мм (по умолчанию 0.300 — стандартный для гранита)
  step_x_mm: null       # шаг винта X (null = auto из step_mm)
  step_y_mm: null       # шаг винта Y (null = auto из step_mm)
```

В `export.py → export_result()` добавить пересчёт разрешения и ресайз:

```python
# Алгоритм
1. Прочитать machine.step_mm из конфига
2. Вычислить целевое разрешение: dpi = 25.4 / step_mm
3. Если stone_type задан (фича #11) — скорректировать шаг по умолчанию
4. Ресайз изображения до целевого размера в пикселях:
   - Физический размер = image_pixels / current_dpi (дюймы)
   - Целевые пиксели = physical_size * target_dpi
   - Или: если физический размер задан в конфиге (ширина/высота в мм),
     то target_pixels = (size_mm / 10) * (10 / step_mm) = size_mm / step_mm
5. Сохранить BMP с установленным DPI в метаданных
6. Логировать: "BMP saved: {width}×{height} px, {dpi} dpi, step={step_mm} mm"
```

**Параметры конфига:**

- `machine.step_mm` — шаг гравировки в мм (0.10–0.50, по умолчанию 0.300)
- `machine.workpiece_width_mm` — ширина заготовки в мм (опционально, для авто-ресайза)
- `machine.workpiece_height_mm` — высота заготовки в мм (опционально)

**Связь с другими фичами:**

- Фича #11 (тип камня) → автоматически предлагает шаг по умолчанию
- Фича #7 (неоднородность) → при высокой неоднородности шаг можно уменьшить для компенсации
- Фича #8 (симуляция) → превью должен учитывать целевое разрешение BMP

**Статус:** ❌ Не реализовано

## 11. Тип камня (гранит/мрамор/габбро) → адаптивный шаг и слияние точек — 🔧 ключевой параметр

Источник: руководство по эксплуатации График-3К (Manual_122a.pdf, разделы 11.5, 11.7, 11.11).

Разные породы камня по-разному реагируют на ударную и лазерную гравировку. Мягкий камень (мрамор) при малом шаге даёт **слияние точек** — соседние удары перекрывают друг друга, изображение «перебивается» (пересвечивается). Твёрдый камень (габбро) позволяет использовать мелкий шаг без слияния.

**Рекомендованные шаги из мануала САУНО:**

| Тип камня | Шаг (ударный), мм | Шаг (лазерный), мм | Особенности |
|---|---|---|---|
| Гранит | 0.300 | 0.125–0.250 | Стандартный, баланс детализации и скорости |
| Мрамор | 0.350–0.400 | — | Мягкий, точки сливаются; глубина до 1.5 мм |
| Габбро | 0.275 | 0.275 | Твёрдый, мелкий шаг без слияния |
| Базальт | 0.225 | 0.225 | Очень твёрдый, максимальная детализация |

**Связь с `stone_heterogeneity` (фича #7):**

Тип камня **должен коррелировать** с параметром `stone_heterogeneity` — они описывают разные аспекты одного и того же материала:

- `stone_type` — **макро-свойство**: порода определяет твёрдость и склонность к слиянию точек → влияет на шаг станка
- `stone_heterogeneity` — **микро-свойство**: пятнистость/зернистость конкретного камня → влияет на контраст и резкость ретуши

**Рекомендованная корреляция:**

| stone_type | stone_heterogeneity по умолчанию | Примечание |
|---|---|---|
| granite | 2 | Типичный гранит — средняя зернистость |
| marble | 1 | Мрамор однороднее, но мягче → слияние точек |
| gabbro | 3 | Габбро зернистее, но твёрже → без слияния |
| basalt | 4 | Базальт очень зернистый и твёрдый |

При выборе `stone_type` пайплайн автоматически:

2. Предлагает `machine.step_mm` по умолчанию
3. Корректирует параметры ретуши через механизм фичи #7

## 9. Цикл «контраст для камня» — повторная обработка — 📈 улучшение воркфлоу

Источник: видео Engrave — ретушёры работают циклом: обработал → проверил на камне → вернулся → усилил контраст → снова проверил. Сейчас пайплайн однопроходный. Нужно добавить возможность повторной обработки с усиленными параметрами для компенсации потерь на камне.

Это **производная фича** от #7 (неоднородность) и #8 (симуляция). Если ретушёр видит, что симуляция на камне выглядит плоско — он нажимает «Усилить для камня», и пайплайн прогоняет изображение повторно с адаптированными параметрами.

**Реализация:**

Добавить метод `process_stone_boost()` в `pipeline.py`:

```python
# Алгоритм
1. Взять текущий результат пайплайна (не исходник!)
2. Применить усиленные корректировки на основе stone_heterogeneity:
   - Levels: уменьшить гамму (контраст ↑)
   - Unsharp Mask: увеличить процент (детали ↑)
   - Brightness: слегка уменьшить (тёмные участки камень воспроизводит лучше)
3. Маска защиты лица — не пересушить кожу при усилении
4. Вернуть результат
```

**Параметры конфига:**

- `stone_boost: true | false` — включить усиление контраста для камня
- Переиспользует `stone_heterogeneity` из фичи #7 для расчёта коэффициентов

**Интеграция с Web UI:**

- Кнопка «Усилить для камня» после первичной обработки
- Автоматически адаптирует параметры на основе `stone_heterogeneity`
- Показать: до усиления | после усиления | симуляция на камне

**Эталонный воркфлоу (из видео):**

1. Ретушь готова → проверить в Engrave предпросмотр
2. На камне выглядит плоско → вернуться в Photoshop
3. Яркость/Контрастность: уменьшить яркость, увеличить контраст
4. Levels: уменьшить гамму
5. Smart Sharpen: усилить резкость
6. Dodge/Burn: выправить пересветы/провалы
7. Снова проверить в Engrave → повторить если нужно

**Статус:** ❌ Не реализовано

## 12. Стохастический дизеринг для экспорта BMP — 🆕 новая фича

Источник: видео о коммерческом Photoshop-плагине «Стохастика Pro 3.1» (сторонняя разработка для гравировщиков).

**Проблема:** стандартный Bitmap-режим Photoshop (и Jarvis/Stucki дизеринг в текущем `export.py`) размещает точки **изолированно** — каждая точка стоит сама по себе. На камне это приводит к тому, что мелкие одиночные точки «пропадают» — камень их не воспроизводит, полутона разрушаются, изображение выглядит зернистым и плоским.

**Решение:** стохастический дизеринг — точки **соединяются в переплетающиеся цепочки** («хаотичные змейки»). Изображение становится более цельным, полутона читаются лучше, результат на камне заметно выигрывает по сравнению с обычным bitmap.

**5 уровней жёсткости (из видео плагина):**

| Режим | Описание | Рекомендация из видео |
|---|---|---|
| SuperFine | Максимально близок к обычному bitmap, точки минимально связаны | Для текста, мелких деталей |
| Fine | Точки слегка переплетены | **Рекомендован для камня** (ударный + лазер) |
| Medium | Умеренное переплетение, более «змеистый» паттерн | **Рекомендован для камня** (ударный + лазер) |
| PreMax | Сильное переплетение, крупные змейки | Для мягкого камня / крупного шага |
| Max | Максимальное слияние, очень плотные цепочки | Для мрамора / большого шага |

**Реализация:**

Новый метод `save_bmp_stochastic()` в `export.py`:

```python
# Алгоритм стохастического дизеринга
1. Конвертация grayscale → промежуточный результат Jarvis/Stucki
2. Морфологическое связывание точек (ключевое отличие от обычного FS):
   a. Для каждого белого пикселя найти ближайших соседей (4- или 8-связность)
   b. Если сосед тоже белый — соединить (оставить как есть)
   c. Если сосед чёрный, но исходный grayscale ≥ порога связности —
      превратить соседа в белый (расширить цепочку)
   d. Порог связности зависит от уровня жёсткости:
      - SuperFine: порог высокий (связываем редко, ~10% кандидатов)
      - Max: порог низкий (связываем агрессивно, ~60% кандидатов)
3. Итеративное распространение цепочек:
   - Каждая итерация: просмотреть белые пиксели на границе цепочек
   - Добавить к цепочке ближайший «почти белый» сосед
   - Количество итераций = уровень жёсткости (1 для SuperFine, 5 для Max)
4. Балансировка плотности:
   - После связывания проверить общую долю белых пикселей
   - Если доля увеличилась больше допустимого → удалить самые слабые связи
   - Допустимое увеличение: SuperFine +2%, Fine +5%, Medium +10%, PreMax +18%, Max +25%
5. Сохранить как 1-bit BMP
```

**Альтернативный алгоритм (Blue Noise Stochastic Screening):**

```python
# Более математически строгий подход
1. Сгенерировать blue noise threshold matrix (пороговая матрица синего шума)
   - Размер матрицы зависит от уровня жёсткости:
     SuperFine = 32×32, Fine = 64×64, Medium = 128×128
2. Для каждого пикселя: если grayscale[i,j] > threshold[i%N, j%N] → белый
3. Дополнительно: морфологический bridge-оператор для соединения
   близких одиночных точек (cv2.morphologyEx с MORPH_CLOSE)
4. Результат — более стохастическое, но визуально связное распределение
```

**Параметры конфига:**

```yaml
export:
  dither_mode: stochastic    # standard | floyd_steinberg | stochastic
  stochastic_level: fine     # superfine | fine | medium | premax | max
```

**Интеграция с export.py:**

Добавить третий путь в `export_result()`:

```python
if fmt == "bmp_stochastic" or (fmt == "bmp" and dither_mode == "stochastic"):
    save_bmp_stochastic(img, bmp_path, level=stochastic_level, machine_type=machine_type)
```

**Интеграция с другими фичами:**

- Фича #11 (тип камня): `point_merge_risk = "high"` (мрамор) → автоматически предложить `stochastic_level: premax` или `max`, т.к. камень всё равно «сольёт» точки — лучше контролировать этот процесс алгоритмически
- Фича #10 (разрешение BMP): стохастический дизеринг чувствителен к разрешению — при низком dpi (крупный шаг) змейки будут крупнее, при высоком — мельче
- Фича #8 (симуляция): симуляция должна показывать стохастический паттерн, а не просто blur

**Связь с комбинированным режимом Engrave (фича #11):**

Стохастический дизеринг из плагина по сути решает ту же задачу, что комбинированный режим A/B/C в Engrave — сделать точки не изолированными, а связанными. Разница в подходе: Engrave управляет связностью на уровне станка (шаг + плотность), а стохастический дизеринг — на уровне изображения (BMP). Оба метода можно комбинировать.

**Эталонный воркфлоу (из видео плагина):**

1. Ретушь готова, все слои видны (grayscale)
2. Запустить плагин «Стохастика Pro»
3. Выбрать уровень жёсткости (Fine / Medium рекомендуются для камня)
4. Плагин автоматически: сливает слои → конвертирует в bitmap → применяет стохастический дизеринг
5. Результат: 1-bit изображение с «змеиным» паттерном вместо отдельных точек
6. Рекомендация: отгравировать тестовую плитку во всех 5 режимах, выбрать лучший

**Статус:** ❌ Не реализовано
